## Design decisions

- **Access rule lives in the service** (`accessScope`): users see only their rows, admins see all. Another user's id is indistinguishable from a missing id (`NOT_FOUND`).
- **List state is in the URL** (`?q=&status=&sortOrder=&page=`). The filter form is a plain `GET` form, so search, filtering, sorting and pagination work without JavaScript (verified by E2E with JS disabled). The combined `sortOrder=field:dir` select is split by `splitSortOrder()`.
- **Invalid URL params never crash the list page.** They fall back to defaults. The API returns 422 for the same input.
- **Stable pagination:** the secondary sort is `id`.
- **Description clearing:** an empty textarea becomes `null` in both create and update, so an edit can remove it.
- **Demo user** is inserted directly (user + `credential` account with Better Auth's `hashPassword`), because the seed runs outside Next.js where `server-only` modules can't load. A test proves Better Auth can sign in with it.

## Known limitations

- Pages under the root `loading.tsx` stream, so `notFound()` renders the 404 UI with HTTP **200** (Next 16 behaviour, documented in `not-found.md`). The API returns real 404s. Delete `src/app/loading.tsx` if real 404 status codes on pages matter more than the instant loading state.
- Search uses `LIKE` (fine for thousands of rows). For large text search, use SQLite FTS5.
