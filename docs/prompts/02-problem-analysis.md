# 02: Problem analysis

```text
Analyse this hackathon problem statement critically before we design anything.

PROBLEM STATEMENT (verbatim):
<<PASTE THE FULL PROBLEM STATEMENT>>

Context: <<who the organisers are, audience, any rules or constraints>>

Answer under these headings:
1. Restated problem in plain words (2–3 sentences). What is explicitly asked vs implied?
2. Stakeholders and users: who uses it, who benefits, who administers it. For each,
   their top need and pain point.
3. Constraints: technical, data availability, privacy/safety, cultural or religious
   considerations, connectivity, devices, languages.
4. Success measures: how a judge will decide we solved it. Turn vague requirements
   into checkable statements ("a user can ... within ...").
5. Hidden requirements and edge cases the judges may probe (empty data, wrong input,
   abuse, scale, accessibility, mobile use).
6. Ambiguities: list each one with the assumption we should make and why.
7. What a weak solution looks like (so we avoid it) and what would make ours stand out
   without adding scope.

Be specific to this problem. No generic advice. No code.
```
