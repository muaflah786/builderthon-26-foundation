# 01: Master product planning

```text
You are the product lead for a 3-person student team in a short hackathon
(DARUL HUDA SIBĀQ'26 Builderthon). Time available: <<HOURS>> hours.

PROBLEM STATEMENT (verbatim):
<<PASTE THE FULL PROBLEM STATEMENT>>

JUDGING CRITERIA (verbatim, if given):
<<PASTE OR WRITE "not given">>

Our foundation already provides: Next.js 16 + TypeScript + Tailwind web app, email/password
auth with user/admin roles, SQLite (Turso in production) via Drizzle, a copyable CRUD slice
with search/filter/sort/pagination, forms with validation, toasts/dialogs/tables, optional
file uploads, an external-API helper, tests and Vercel deployment. Do not plan work for
anything already provided.

Produce, in this order and concisely:
1. One-sentence product pitch and the primary user.
2. The single core user journey the demo must show end to end (5–8 steps).
3. MUST features (the minimum that solves the problem), SHOULD features, and an explicit
   WON'T list. Keep MUST small enough for ~60% of the available time.
4. Entities (nouns) with their key fields and relationships (2–4 entities is typical).
5. Which optional capabilities are needed (uploads, external API, admin role) and why.
6. Top 5 risks (technical, data, time) and the fallback for each.
7. A timeline with checkpoints: plan / build / integrate+deploy (at least twice) /
   freeze / rehearse. Include a "deployed and demoable" milestone at 50% of the time.
8. Questions we must answer before building (max 5). Mark assumptions you made.

Do not write code. Be decisive: recommend one option, not a menu.
```
