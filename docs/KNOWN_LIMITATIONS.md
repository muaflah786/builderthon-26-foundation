# Known limitations and contingency procedures

## Limitations (by design or not yet verified)

| #   | Limitation                                                                                                                                                 | Impact                                                                   | Mitigation / when it matters                                                                                                         |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Deployment to **Vercel + Turso is UNTESTED** (no accounts yet)                                                                                             | The first real deploy may surface config issues                          | Do a full rehearsal deploy **before** competition day (docs/DEPLOYMENT.md). Option B (Node host with SQLite) is verified locally.    |
| 2   | **CI has never run on GitHub**                                                                                                                             | YAML mistakes would only show after the first push                       | Push to GitHub before the event and watch the first run.                                                                             |
| 3   | Rate limiting (Better Auth + `rateLimit()`) is **in-memory, per instance**                                                                                 | On serverless, limits are best-effort                                    | Fine for a demo. Strict limits: Upstash/Redis (DEPLOYMENT.md §Strict rate limiting).                                                 |
| 4   | Pages under the root `loading.tsx` stream, so `notFound()` returns HTTP **200** with the not-found UI (Next 16 behaviour)                                  | Only the status code; the UI and APIs are correct (APIs return real 404) | Delete `src/app/loading.tsx` if real 404 status codes on pages matter.                                                               |
| 5   | Root layout reads the session, so **every page is dynamic** (no static pages)                                                                              | Slightly slower first byte; irrelevant at demo scale                     | Move the session read into `/app/layout.tsx` if a static marketing page is needed.                                                   |
| 6   | **SQLite/libSQL**: single writer, `LIKE` search                                                                                                            | Fine for thousands of rows and a demo                                    | Use FTS5 for big text search; switch to Postgres only if required (ARCHITECTURE.md escape hatch, about 1 hour).                      |
| 7   | No email sending: no email verification, password reset or magic links                                                                                     | Users can't recover passwords                                            | Recipes in docs/modules/t1-auth.md (needs an email provider key).                                                                    |
| 8   | No OAuth/social login                                                                                                                                      | —                                                                        | Recipe in docs/modules/t1-auth.md (needs an OAuth app).                                                                              |
| 9   | Admins are made via `db:studio`/SQL; there is no admin UI                                                                                                  | —                                                                        | Build only if the problem needs it.                                                                                                  |
| 10  | S3/R2 upload driver is **UNTESTED** against a real bucket                                                                                                  | Upload may fail in production                                            | Signing is verified against AWS's vector; test once with real credentials. Local driver is verified.                                 |
| 11  | `db:push` asks for confirmation (strict mode) and fails in non-interactive shells. `db:generate` prompts when one migration both drops and creates tables. | Claude/CI cannot answer prompts                                          | Use `db:generate` + `db:migrate`; drop old tables and add new ones in **separate** generate runs (see COMPETITION_ADAPTATION_GUIDE). |
| 12  | 4 moderate `npm audit` advisories in drizzle-kit's bundled esbuild (dev-only)                                                                              | None at runtime                                                          | Re-check when drizzle-kit releases an update.                                                                                        |
| 13  | No Content-Security-Policy header                                                                                                                          | Defence-in-depth only; inputs are validated and React escapes output     | Add a nonce-based CSP in `proxy.ts` if required (SECURITY_CHECKLIST.md).                                                             |
| 14  | No i18n / RTL layout                                                                                                                                       | Arabic/Malayalam UI would need work                                      | Add only if the problem requires it (`dir="rtl"` + logical Tailwind classes).                                                        |

## Contingency procedures

| Situation                                                       | Do this                                                                                                                                                                                            |
| --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Internet down** during development                            | Everything runs offline once `npm ci` has been done: SQLite file DB, system fonts, no CDN. Keep working locally; deploy later.                                                                     |
| **Internet down at demo time**                                  | `npm run build && npm start` on a laptop with the seeded `local.db` (set a real `BETTER_AUTH_SECRET` and `APP_URL=http://localhost:3000`). Keep a screen recording of the demo as the last resort. |
| **Live site broken** after a deploy                             | Vercel → Deployments → previous deployment → **Promote to Production**. Then `git revert` the bad commit.                                                                                          |
| **Local DB corrupted / migration mess**                         | Delete `local.db`, then `npm run db:migrate && npm run db:seed`.                                                                                                                                   |
| **Migration conflict after merging** two branches               | Keep both schema files; delete the conflicting generated SQL + snapshot + journal entries from the branch merge; run `npm run db:generate` once (integration prompt 08).                           |
| **`npm ci` fails** (network/registry)                           | Retry; use a phone hotspot; as a last resort copy `node_modules` from a teammate's laptop with the same OS and Node version.                                                                       |
| **A teammate's laptop dies**                                    | Clone the repo on another machine and follow WINDOWS_SETUP (20 min). Push often so nothing is lost.                                                                                                |
| **Turso unavailable**                                           | Deploy to a Node host with a persistent disk and `DATABASE_URL=file:/data/app.db` (DEPLOYMENT.md Option B).                                                                                        |
| **Auth broken in production** (`INVALID_ORIGIN`, can't sign in) | Check `APP_URL` equals the exact public origin and `BETTER_AUTH_SECRET` is set; redeploy.                                                                                                          |
| **Running out of time**                                         | Freeze features at T-60; cut SHOULD items; make sure the single core journey works on the deployed site.                                                                                           |
| **Claude produces broken code**                                 | `git diff`, `git restore <file>` or `git revert`; re-run with prompt 09 including the exact error.                                                                                                 |
